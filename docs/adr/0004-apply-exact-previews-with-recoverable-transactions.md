# Apply exact previews with recoverable transactions

Language-server edits can become stale between proposal and filesystem mutation, and no cross-platform filesystem can make an arbitrary multi-resource change perfectly atomic across crashes. `lspctl` will therefore persist a canonical, immutable Preview and require its exact identifier for Application, except when an Agent explicitly preauthorizes edits requested during one language-server command. Application revalidates every bound identity and filesystem precondition, stages and journals the complete plan, records an at-most-once Receipt, and either reaches the intended manifest, rolls back, or exposes Recovery with the exact observed state. Because rollback can still require Recovery, `lspctl` advertises LSP `undo` rather than claiming `transactional` failure handling.
